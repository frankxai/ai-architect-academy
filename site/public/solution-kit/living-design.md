## Choose tools by the work they own

GitHub owns contracts, prose, code, source identities, tests and release receipts. Figma is an editable component and screen review projection. Canva is an editable presentation, workbook, cover and distribution projection. HTML5 owns the working interaction. Hyperframes or Remotion become useful for a narrated, timed export after the interaction and script are accepted. A motion export must preserve exact labels and state; it does not become a runtime receipt.

Use the DTCG 2025.10 token format as an exchange candidate. It is a stable community specification, not a W3C Standard. The accompanying token file is a small format-shaped handoff; no third-party token importer has been tested. Keep exact icons as their original SVG sources and preserve separate provider rights. Generated imagery can supply a character or scene while exact diagrams, typography and factual labels remain deterministic.

The executable practice uses paper, ink and cobalt; Georgia plus system fonts keep the standalone export offline. The Academy retains its Playfair Display/Inter application typography. Do not claim full brand-kernel acceptance when the required design authority files cannot be accessed.

## Delivery roles and authority

One integrating architect owns the user job, decision order, root budget and acceptance contract. Scoped implementers work on disjoint files. A source editor verifies volatile claims. A design reviewer checks use, reading, keyboard, narrow screens and disabled motion. A separate verifier challenges the exact candidate, failures and recovery. Specialist security, rights and legal review remain separate when applicable. Role names are obligations, not claims that experts have participated.

The engine's existing stage agents still write only their designated architecture documents. A Studio implementation mandate must separately name application paths, isolated execution, tenant scope, budgets and credentials. Review, publication, paid actions and production promotion retain the existing human gates.

The maintainer prepares the smallest complete candidate, pins its hash, runs appropriate checks, corrects findings, then presents a concrete release decision. Every admission names the buyer, job, baseline, proof, owner, rights, maintenance cadence, dependencies, time/token ceiling and stop condition. Avoid a fresh platform or repository until permissions, runtime or release ownership justify it.

## Quality and economics

`practice.json` is the proposed metric and proof-obligation register. Observations are null until measured. Targets are proposed thresholds to agree with a customer, not industry benchmarks. Each metric includes a population, denominator and window. Hard failures block the affected release; scores do not average away breaches, false claims or lost work.

Count all attempts, retry/tool cost, abandoned work, correction and support. Compare cost per accepted result against the customer baseline. Show provider consumption only when billable usage is attributable to the chosen account, service, region and period; subtract credits and avoid double counting external model charges. Saved capacity is not revenue. Architecture simplification may lower spend per result while adoption grows total useful workload.

An excellent first pilot proves one complete job, failure, correction and owned export. The current practice desk executes deterministic fixture checks and capsule restore; it does not measure human completion, real-model output, production reliability or billing. Its browser metrics remain an acceptance obligation until measured on a supported browser.

## Underused design moves to test

These are authored hypotheses, not secret knowledge or novelty claims:

1. **Bind acceptance to a revision.** A post-review edit invalidates the affected review even when the screen remains green.
2. **Separate artifact types.** A visualized diagram, executable template and provider-tested deployment need different evidence and cannot inherit each other's status.
3. **Allocate evaluations at the decision seam.** Test the source-access, tool-effect and review boundaries where a correct answer can become an unauthorized action.
4. **Compare a counterfactual.** Run the same frozen tasks on the simplest feasible architecture and one more sophisticated alternative; measure accepted result, recovery and all-attempt cost.
5. **Budget reviewer effort.** A faster draft can produce more correction work. Measure the full path to acceptance.
6. **Exercise exit early.** Export, restore and reproduce one project before adding private data or commercial dependency.
7. **Track source impact.** A changed source should name affected claims, profiles, templates, chapters and tests before a correction is accepted.

## Maintenance

Use the existing portfolio maintenance controller. This kit does not install a scheduler. A source check records requested and resolved URL, transport status, inspection scope, date and next review. HTTP 200 alone does not establish correct content, account access or integration. Link checks must not traverse credentials, private customer files, local addresses or arbitrary imported URLs.

The existing draft PRs own this candidate. Merge and production publication require the named repository authority. Revert the candidate and regenerate the previous source-pinned Academy projection to roll back; no customer data migration is introduced.
