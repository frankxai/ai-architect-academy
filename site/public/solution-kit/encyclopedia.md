# AI architecture encyclopedia: initial working entries

Each entry is an architectural decision with an evidence obligation. Stable IDs, alternative, owner, source pointers, freshness and reference maturity are recorded in [encyclopedia.json](encyclopedia.json). Source pointers are contextual reading; they do not externally validate the authored prescriptions. This is an initial authored reference set, not a complete taxonomy or proof of professional competence.

| Entry | Decision | Failure to test | Required artifact |
|---|---|---|---|
| Accepted outcome | Define the human result and denominator before agent activity | Plausible output that fails the actual task | Frozen cases, acceptance owner, result ledger |
| Model seam | Separate provider credentials, transport and capability policy | Fallback changes privacy or tool behavior | Provider adapter contract and differential eval |
| Context contract | Admit sources by rights, purpose, freshness and user access | Unauthorized or obsolete retrieval | Source ledger, ACL cases and deletion propagation |
| Workflow versus agent | Use a fixed workflow until decisions require open reasoning | Autonomous detours inflate cost without value | Baseline comparison and bounded stop rule |
| Durable execution | Persist effects and checkpoints beyond request life | Duplicate action after restart or timeout | Idempotency key, restart and cancellation tests |
| Tool authority | Trusted gateway checks actor, tenant, input and resource | Prompt injection expands permissions | Typed tool contracts and denial fixtures |
| Customer experience | Make progress, correction, stop and export visible | Attractive screen conceals stale/failing work | Service blueprint and tested interaction states |
| Topology | One ID registry backs every component and edge | Diagram and deployment describe different systems | Canonical graph and semantic export checks |
| Data flow | Classify every transferred payload and trust crossing | Trace captures personal data or secrets | Data inventory, access tests, trace redaction |
| Human review | Bind review to exact artifacts and decision rights | Review applies to a changed release | Immutable receipt and change invalidation |
| Cost per accepted result | Count failures, retries, review and support | Cheap inference hides expensive correction | Full-attempt cost ledger and baseline |
| Consumption | Attribute actual billable workload usage | Credits/API resale counted as platform demand | Metered service/account/region ledger |
| Provider portability | Define the export boundary and replacement test | Claimed neutrality fails on proprietary state | Export/import and adapter contract cases |
| Operational readiness | Name owner, SLO, alert, recovery and teardown | READY deployment cannot complete customer journey | Domain/revision receipt and incident drill |
| Intelligence level | Select deterministic, assistive, workflow or bounded agent | Extra agents only add latency and agreement bias | Controlled comparative evaluation |
| Research provenance | Separate fact, inference, proposal and uncertainty | Agent-written certainty outruns sources | Claim/source ledger and expiry dependency map |
| Visual evidence | Select exact code/spec diagrams or conceptual generated media | Wrong icon or arrow changes meaning | Format policy, icon registry and export review |
| Industry solution | Ground use case in observed work and sector constraints | Generic automation misses actual operating needs | Current industry sources and customer pilot |
| Partner status | Distinguish upstream project, target and signed relationship | Logo falsely suggests endorsement | Agreement/status/expiry record |
| Invention status | Distinguish original proposal, benchmarked contribution and legal claim | Combination presented as patented novelty | Prior-art investigation and independent experiment |

For a deployable workload, attach source repository, immutable revision, license, supported host, dependency lock, configuration contract, threat model, operational owner and release receipt. A diagram-only entry stays visualized. The encyclopedia links to existing architecture stages instead of inventing a second competency graph.
