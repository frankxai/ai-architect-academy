# Visual production recipes

Working reference, 11 October 2026. Prescriptions below are authored guidance. The API catalog statements are scoped to the official sources in `sources.json`; no image was generated or API configuration executed for this package.

## Current image interfaces

The OpenAI Responses image-generation guide currently recommends `gpt-image-2.5-sunburst` for precise editing and `gpt-image-2.5-flare` for fast generation. The image API reference lists September 8 snapshots for both. Pin a supported snapshot for an evaluated API template, then retest before migration. The official deprecation page schedules the API alias `chatgpt-image-latest` for removal on 1 December 2026. Do not encode that alias as a durable production dependency. These API facts do not establish the exact backend selected by ChatGPT or by an image tool in this session. Record the actual interface and exposed model metadata; mark unavailable identifiers unknown.

Transparent cutouts require a supported model and PNG/WebP output in the documented API. For a tool-based workflow, request transparency explicitly. For edits, supply the exact original and preserve approved geometry/identity. Review the actual result for unintended changes; a requested edit does not prove it occurred correctly.

## Choose the representation

| Job | Deliverable | Evidence obligation |
|---|---|---|
| Exact cloud architecture | Canonical graph to SVG/diagrams.net; official icon registry | Components, flows, rights, labels and deployed state agree |
| Editable topology | React Flow application connected to versioned graph | Permission, save/conflict, import/export and undo tests |
| Data and tool authority | Typed edge contracts plus sequence/DFD | Direction, payload, tenant, authorization, retries and timeout |
| Working screen/mobile flow | HTML/React components from interaction specification | Keyboard, viewport, forms, errors, recovery and export |
| UI exploration | Generated screen concept | Mark visual concept; replace with tested components |
| Team story/workflow characters | Generated illustration plus code-composed captions | Roles match approved story; no invented product semantics |
| Factual quantitative chart | Plotting library/data specification | Reproducible data, units, denominator and uncertainty |
| Animation | Timeline/state specification to code renderer | Event order and reduced-motion equivalent |

## Reusable prompt briefs

**Role illustration.** Create three recurring characters for a customer research workflow: project owner, research assistant and independent reviewer. Editorial ink and cobalt on warm paper, approachable professional expressions, distinct silhouettes. Show a source document passing from researcher to reviewer and returning with a correction. Leave caption spaces blank. No provider logos, fabricated product icons or embedded data-flow arrows. Mark the final composed artifact “Workflow story / conceptual.” Use only synthetic documents. Deliver a wide scene and separate transparent character cutouts when the interface supports them.

**Desktop concept.** Explore a company R&D workbench with a next-decision card, source list, two architecture alternatives, unresolved-evidence panel and review queue. Warm paper, dark ink, restrained cobalt, strong text hierarchy and generous spacing. Show pending and failed states as clearly as success. Keep customer/project names synthetic. This is a concept image; exact text, controls and architecture are subsequently composed in code from the approved specification.

**Mobile sequence.** Propose four portrait storyboard frames: open pending decision; inspect source permission; request correction; export reviewed result. Maintain the same character and project. Leave numbered caption areas blank for precise code-composed labels. Preserve the distinction between request, approval and publication. The implementation must support all frames and recovery through accessible HTML controls.

**Image edit.** Reference the approved source image. Change only the named subject, expression or scene property. Preserve character identity, palette, composition and untouched regions. Describe the exact requested change and forbidden collateral changes. Inspect the resulting image beside the original; reject altered approved content rather than assuming preservation.

**Architecture composition.** Generate a conceptual background or character layer only. Render components, approved official icons, source IDs and arrows from the canonical graph above it. Keep narrative art in a separate layer. Acceptance compares the final component and edge IDs to the specification and inspects arrow direction/legibility at desktop and mobile export sizes.

## Asset receipt

Store brief revision, input-image digests and rights, actual interface/model identifier when exposed, generation/edit date, prompt, output digest, approval owner, rejected attempts and edits. The asset is conceptual until exact composition and review pass. Image production cost belongs in the all-attempt delivery ledger. Keep private source material out of public prompts and exports. An image may explain a workflow; runtime evidence comes from its execution.
